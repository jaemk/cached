# cached 4.0.2 -> 4.0.3 Migration (Agent Instructions)

Versions: `cached 4.0.2` -> `cached 4.0.3`

`cached_proc_macro` and `cached_proc_macro_types` did not change; leave them pinned at
`3.0.1` and `3.0.0` respectively if pinned directly.

## Breaking changes

None. The minimum `redis` version moves from 1.0 to 1.2.3 so the redis features resolve `lru`
0.18 (RUSTSEC-2026-0253 affects `lru` 0.16). No public API or runtime behavior changed.

## New APIs

None.

## Detection

Only relevant with a `redis_*` feature enabled and `redis` pinned below 1.2.3 elsewhere in the
dependency graph:

```
cargo tree -i redis
```

## Required Cargo.toml change

```toml
# Before
cached = "4.0.2"

# After
cached = "4.0.3"
```

If the project also depends on `redis` directly, its requirement must admit 1.2.3 or later
(e.g. `redis = "1.2.3"`, or `"1"` with `cargo update -p redis`).

## VERIFY

```
cargo update -p cached
cargo build
cargo test
```

No new compile errors are expected from the version bump.
