# Upgrading from cached 2.x to 3.0

cached 3.0 is a major release. The largest changes are a new disk backend (redb replaces sled),
a reworked redis feature layout that splits the runtime and TLS choices onto their own axes, and a
public-API cleanup across the store constructors, traits, and macro attributes.

This is the human walkthrough of the high-traffic changes. For the complete, exhaustive list of
every breaking change with detection greps, see the
[agent-oriented guide](2.0-to-3.0.md).

## Before you upgrade: toolchain requirement

cached 3.0 requires Rust >= 1.92. The binding constraint is the `async` / `async_core` feature:
the default method bodies on `CachedGetOrSetAsync` do not compile before 1.92, due to a rustc
borrowck limitation (rust-lang/rust#100013). Update your toolchain if you are below 1.92. Any
Rust >= 1.92 works; you do not need the latest stable.

## Quick summary

Macro attribute changes (most common):
- `size = N` is removed. Use `max_size = N` (the 2.x deprecation alias is gone).
- `ttl = N` (bare integer seconds) is removed. Use `ttl_secs = N`, `ttl_millis = N`, or a
  `Duration` expression string `ttl = "Duration::from_secs(N)"`.
- `unbound` is removed. A bare `#[cached]` already builds an `UnboundCache`.
- `refresh = true` now requires a TTL (previously it was silently ignored without one).

Feature renames (check your `Cargo.toml`):
- `disk_store` -> `redb_store`.
- Redis runtime and TLS are now separate feature axes (details below).
- `redis_ahash`, `wasm`, and `async_tokio_rt_multi_thread` are removed.
- `serde` is no longer a selectable feature. Drop it from your feature list; the codec is pulled
  in directly by `redis_store` and `redb_store`.

Store and type renames:
- `DiskCache*` -> `RedbCache*` (no alias kept).
- `ShardedCache*` -> `ShardedUnboundCache*` (no alias kept).

Construction and trait imports:
- I/O store `builder()` methods take the primary required field positionally (`RedbCache::builder(name)`, `RedisCache::builder(prefix)`, `AsyncRedisCache::builder(prefix)`).
- The short method aliases (`get`/`set`/`len`/...) moved to extension traits; `use cached::prelude::*;`
  brings everything in.
- `CachedAsync` is renamed to `CachedGetOrSetAsync`.

Behavior:
- The default `#[cached]` write behavior is unchanged from 2.x (no synchronization).
  `sync_writes = "by_key"` is a new opt-in.
- Serialize-backed stores self-heal undecodable entries by default (opt out with
  `strict_deserialization(true)`).
- `retain` now returns `usize` (the number of entries removed) instead of `()`.

## Step-by-step upgrade

### 1. Macro attribute changes

`size` becomes `max_size`:
```rust
// Before
#[cached(size = 100)]
// After
#[cached(max_size = 100)]
```

`ttl = <integer>` becomes one of three forms:
```rust
// Before
#[cached(ttl = 60)]
// After (whole seconds, preferred)
#[cached(ttl_secs = 60)]
// After (milliseconds, new)
#[cached(ttl_millis = 500)]
// After (arbitrary Duration expression, must be a string literal)
#[cached(ttl = "cached::time::Duration::from_secs(60)")]
```
The three forms are mutually exclusive. The same forms apply to `#[once]` and
`#[concurrent_cached]`. Builder `.ttl(Duration)` is unchanged, and builders gain `.ttl_secs(n)` /
`.ttl_millis(n)` shorthands.

`unbound` is gone (it was redundant), and `refresh = true` now needs a TTL:
```rust
// Before (refresh silently did nothing without a ttl)
#[cached(refresh = true)]
// After
#[cached(ttl_secs = 60, refresh = true)]
```

### 2. Feature renames and the redis axis split

Rename `disk_store` to `redb_store`:
```toml
# Before
cached = { version = "3", features = ["disk_store"] }
# After
cached = { version = "3", features = ["redb_store"] }
```

Redis is now split into three independent axes: a runtime, an optional TLS backend, and optional
capabilities. Pick one from each axis you need:
- Runtime: `redis_tokio` or `redis_smol` (required for any async redis use).
- TLS (optional): `redis_tokio_native_tls` / `redis_tokio_rustls` (or the `redis_smol_*` twins).
  The runtime features no longer imply native-tls, so a `rediss://` URL needs an explicit TLS
  feature.
- Capabilities (optional, additive): `redis_async_cache` (client-side caching) and
  `redis_connection_manager` (auto-reconnect). Neither pulls a runtime on its own, and
  `redis_connection_manager` is now a per-cache opt-in via `.connection_manager(true)` rather than
  a global swap.

```toml
# Before (2.x): the capability implied the tokio runtime
cached = { version = "2", features = ["redis_connection_manager"] }
# After: pair the capability with a runtime, opt in per cache
cached = { version = "3", features = ["redis_connection_manager", "redis_tokio"] }
```

`redis_ahash`, `wasm`, and `async_tokio_rt_multi_thread` are removed. The first gated no cached
code; `wasm` was unnecessary (wasm-compatible time is transparent); and for multi-threaded async
tests, add `tokio = { version = "1", features = ["rt-multi-thread", "macros"] }` to your own
`[dev-dependencies]`.

### 3. Store and type renames

The sled-backed disk store is now redb-backed and named `RedbCache`:
```rust
// Before
use cached::stores::DiskCache;
// After
use cached::stores::RedbCache;
```
The old `DiskCache` / `DiskCacheBuilder` / `DiskCacheError` / `DiskCacheBuildError` names are
removed (no alias). Existing on-disk caches are not read across the format change (entries
recompute on first access); the old sled directories linger as dead files and can be deleted
manually.

`ShardedCache` is renamed to `ShardedUnboundCache`:
```rust
// Before
let c: ShardedCache<String, u32> = ShardedCache::new();
// After
let c: ShardedUnboundCache<String, u32> = ShardedUnboundCache::new();
```

### 4. Store construction

The I/O-store builders now take the primary required field positionally:
```rust
// Before
let b = RedbCache::<String, String>::new("my-cache");
let b = RedisCache::<String, String>::new("prefix", ttl);
// After
let b = RedbCache::<String, String>::builder("my-cache").build()?;
let b = RedisCache::<String, String>::builder("prefix").ttl(ttl).build()?;
```
The redis TTL is now optional; omit `.ttl(...)` to store keys without expiry.
A missing required field now returns `Err(BuildError::MissingRequired(...))` from `build()` rather
than failing at construction.

Two builder renames on the in-memory stores:
- `.refresh(...)` -> `.refresh_on_hit(...)`.
- `.capacity(n)` (the preallocation hint) -> `.initial_capacity(n)`, distinct from `.max_size(n)`
  (the eviction bound).

New `::new()` conveniences exist on the in-memory and sharded stores when you want a default
configuration:
```rust
let cache: LruCache<String, u32> = LruCache::new(100);
let cache: TtlCache<String, u32> = TtlCache::new(Duration::from_secs(60));
```

The default shard count of the LRU-bounded sharded stores (`ShardedLruCache`, `ShardedLruTtlCache`,
`ShardedExpiringLruCache`) is now scaled down for small `max_size` (roughly `max_size / 16` shards,
capped by the CPU-derived default), so `ShardedLruCache::new(100)` reports 8 shards and a
`capacity()` of 128 rather than the much larger shard count and capacity a high-core-count host
produced before. An explicit `.shards(n)` still overrides this.

### 5. Trait imports

The short method aliases (`get`, `set`, `remove`, `len`, `is_empty`, ...) moved off the `Cached` /
`ConcurrentCached` core traits onto blanket extension traits `CachedExt` / `ConcurrentCachedExt`.
The core traits keep only the `cache_`-prefixed methods. The simplest fix is the prelude:
```rust
use cached::prelude::*; // core + extension traits + the common concurrent traits
```
If you import traits individually, add `CachedExt` (or `ConcurrentCachedExt`) alongside the core
trait, or call the `cache_`-prefixed method directly.

Two related splits, both aimed at letting you import the concurrent traits together without
`E0034` "multiple applicable items in scope":
- The shared concurrent helpers (`cache_size`/`len`/`is_empty`, and the TTL controls) moved to
  `ConcurrentCacheBase` and `ConcurrentCacheTtl`. The prelude brings them in.
- `ConcurrentCachedAsync`'s cache methods gained an `async_` prefix (`async_cache_get`,
  `async_cache_set`, ...), so they no longer collide with the synchronous `ConcurrentCached`
  methods on a store that implements both.

The in-memory async-closure trait `CachedAsync` is renamed to `CachedGetOrSetAsync`:
```rust
// Before
use cached::CachedAsync;
let v = cache.async_get_or_set_with(key, || async { value }).await;
// After
use cached::CachedGetOrSetAsync;
let v = cache.async_cache_get_or_set_with(key, || async { value }).await;
```
Its four sync passthroughs (`async_cache_get`/`_set`/`_remove`/`_clear` on an in-memory store) are
removed; call the synchronous `Cached` methods directly (no `.await`).

### 6. `get_or_set_with` returns `&V`

`cache_get_or_set_with` / `cache_try_get_or_set_with` (and the async twins) now return `&V` /
`Result<&V, E>` instead of `&mut V`. Read-only call sites usually need no change. To mutate the
returned value, switch to the new `*_mut` variants (`cache_get_or_set_with_mut`, etc.).

### 7. `sync_writes` is unchanged (nothing to migrate)

Both the default and the `"by_key"` opt-in are unchanged from 2.x, so there is nothing to do here.
This entry is a reminder of the semantics, not a break.

A bare `#[cached]` still runs concurrent first-calls for the same key independently, matching 2.x
(and Python's `functools.lru_cache`). If you want per-key deduplication so the body runs at most
once per key per miss window, opt in:
```rust
#[cached(sync_writes = "by_key")]
fn compute(x: u64) -> u64 { expensive(x) }
```
Note that the `"by_key"` bucket lock is held across the whole function body, so do not use it on
recursive or re-entrant memoized functions (colliding keys deadlock), and concurrent readers of
the same key serialize. Note also that `sync_writes` cannot be combined with `result_fallback`:
an explicit non-disabled `sync_writes` alongside `result_fallback` is a compile error.

### 8. Error handling on serialize-backed stores

The store error enums (`RedbCacheError`, `RedisCacheError`, and their build-error twins) dropped
the redundant `Error` suffix from variant names, became `#[non_exhaustive]` struct variants, and
now carry boxed sources (`Box<dyn std::error::Error + Send + Sync>`) rather than concrete backend
types. An exhaustive `match` needs a wildcard arm.

By default, a serialize-backed store self-heals an entry it cannot decode: `cache_get` deletes the
offending entry and returns `Ok(None)` (a transparent miss the caller repopulates). If you would
rather have decode failures surfaced, opt into strict mode:
```rust
let cache = RedbCache::<String, Data>::builder("my-cache")
    .strict_deserialization(true)
    .build()?;
```
Redis values are now stored as MessagePack rather than JSON. Old 2.x JSON entries are read
transparently (a backward-read fallback) and rewritten as MessagePack on their next write, so a
rolling upgrade does not invalidate a shared redis cache.

## Additional breaking changes from the final 3.0 API

Breaking changes not covered by the sections above. For full Detection/Action entries see the
[agent-oriented guide](2.0-to-3.0.md).

### `cache_set_ref` / `async_cache_set_ref` return `Result<(), _>`

The borrowed-set methods on `SerializeCached` / `SerializeCachedAsync` no longer return the
previous value. The return type is now `Result<(), Self::Error>`. This removes the per-write GET
on IO stores (Redis, redb).

If you have a custom `impl SerializeCached`:
```rust
// Before
fn cache_set_ref(&self, k: &K, v: &V) -> Result<Option<V>, Self::Error> {
    // ... write ...
    Ok(Some(prev))
}
// After
fn cache_set_ref(&self, k: &K, v: &V) -> Result<(), Self::Error> {
    // ... write ...
    Ok(())
}
```
To get the previous value, call `cache_get` before the set.

### Concurrent introspection is `cache_size` / `cache_is_empty`

The introspection methods on `ConcurrentCacheBase` are `cache_size` and `cache_is_empty`. The
shorter `len` / `is_empty` names live on the `ConcurrentCachedExt` alias trait (new in 3.0; the
concurrent traits carried neither name in 2.0.2), returning `Result<Option<usize>, _>` /
`Result<Option<bool>, _>`. `use cached::prelude::*;` brings them in.

The concrete sharded types still have inherent `len()` / `is_empty()` returning plain `usize` /
`bool`; those take call-site priority over the alias-trait methods and are unaffected.

### Redis and redb `::builder()` takes a required positional argument

The primary identifier moves back to a positional argument on the cache type's `builder` method:

```rust
// Before (the intermediate no-arg form some 3.0 release candidates shipped)
let b = RedbCache::<String, String>::builder().name("my-cache");
let b = RedisCache::<String, String>::builder().prefix("my_prefix");
// After
let b = RedbCache::<String, String>::builder("my-cache");
let b = RedisCache::<String, String>::builder("my_prefix");
```

`RedisCacheBuilder::new()` and `RedbCacheBuilder::new()` (builder-struct constructors) still
take no arguments and chain with setters. Only the `CacheType::builder(x)` shorthand changed.

### Redis TTL is now optional

`RedisCache::builder("prefix").build()` no longer returns `MissingRequired("ttl")`. An unset TTL
means entries are written without an expiry command and never expire. Set `.ttl(Duration)` if you
want expiry.

### Redis builders reject an empty prefix

`RedisCacheBuilder::build()` / `AsyncRedisCacheBuilder::build()` now return
`Err(BuildError::InvalidValue { field: "prefix", .. })` for a prefix explicitly set to `""`
(2.x accepted it silently). The prefix is what distinguishes logical caches sharing a namespace;
two that both leave it empty share one keyspace and one `cache_clear` scope, so each clears the
other's entries. Give each logical cache a distinct non-empty prefix. `#[concurrent_cached(redis = true)]` supplies the
function name as the prefix, so macro-generated caches are unaffected.

### `#[concurrent_cached(disk = true, cache_prefix_block = ...)]` is a compile error

This combination previously compiled but silently ignored `cache_prefix_block`. It is now a
compile error. Remove `cache_prefix_block` from disk-backed annotations; disk stores use `name`
as the redb table identifier.

### `Resp2DowngradeWithClientSideCaching` requires `redis_async_cache`

The `RedisCacheBuildError::Resp2DowngradeWithClientSideCaching` variant is declared only when
the `redis_async_cache` feature is enabled (it was never constructible without it). If you
match on it, gate the arm with `#[cfg(feature = "redis_async_cache")]` or rely on the `_` arm
the `#[non_exhaustive]` enum already requires.

### `Return<T>` fields are now private

The `value` and `was_cached` fields on `Return<T>` (from `cached_proc_macro_types`) went private.
Code that accessed them directly produces `field value of struct Return is private` or
`field was_cached of struct Return is private` compile errors.

```rust
// Before (2.x): direct field access
let r: Return<String> = my_cached_fn();
println!("{}", r.value);
if r.was_cached { ... }
```

```rust
// After (3.x): deref, into_inner(), and was_cached()
let r: Return<String> = my_cached_fn();
println!("{}", *r);             // deref coerces to &T
println!("{}", r.into_inner()); // consumes r, returns T
if r.was_cached() { ... }
```

### `cache_contains` / `async_cache_contains` are now required on the concurrent traits

If you have a custom `impl ConcurrentCached` or `impl ConcurrentCachedAsync` for your own store,
you must add these methods. The `V: Clone` bound that was on the defaulted rc versions is gone.

```rust
fn cache_contains(&self, k: &K) -> Result<bool, Self::Error> {
    self.cache_get(k).map(|v| v.is_some())
}

async fn async_cache_contains(&self, k: &K) -> Result<bool, Self::Error> {
    self.async_cache_get(k).await.map(|v| v.is_some())
}
```

Note that the trait declares `async_cache_contains` in RPIT form
(`impl Future<Output = ...> + Send` with `where Self: Sized + Sync, K: Sync`); the
`async fn` above desugars to it, so either spelling works in an impl. The machine guide
shows the full RPIT form.

The sync `cache_contains` has no `Self: Sized` bound, so it is now callable through
`dyn ConcurrentCached<K, V, Error = E>`. If your rc-era impl copied a `where Self: Sized` onto its
`cache_contains`, drop it to match the trait.

If you only use the built-in sharded, redis, or redb stores, no change is needed.

### `CacheTtl` / `CacheEvict` removed from concurrent stores

`CacheTtl` and `CacheEvict` are single-owner (`&mut self`) traits, no longer implemented for
`RedisCache`, `AsyncRedisCache`, `RedbCache`, or the sharded stores. Use the `&self`
equivalents on concurrent stores:

```rust
use cached::{ConcurrentCacheTtl, ConcurrentCacheEvict};
// Before
CacheTtl::set_ttl(&mut store, Duration::from_secs(30));
let n = CacheEvict::evict(&mut store);
// After
store.set_ttl(Duration::from_secs(30)); // ConcurrentCacheTtl; works through Arc/static
let n = store.evict();                  // ConcurrentCacheEvict, or the inherent evict(&self)
```

`ConcurrentCacheEvict` is implemented by the TTL/expiring sharded stores (`ShardedTtlCache`,
`ShardedLruTtlCache`, `ShardedExpiringCache`, `ShardedExpiringLruCache`). The single-owner
in-memory stores keep `CacheTtl` / `CacheEvict` unchanged.

### `TtlSortedCache::set_ttl` inherent method removed

Call `set_ttl` through the `CacheTtl` trait (same as `TtlCache` and `LruTtlCache`):

```rust
use cached::CacheTtl; // or `use cached::prelude::*;`
cache.set_ttl(Duration::from_secs(30));
```

### `Cached` gained `type Error`; in-memory set paths are infallible

`Cached` has an associated `type Error`, and `cache_try_set` / `try_set` return
`Result<Option<V>, Self::Error>` instead of `Result<Option<V>, Box<dyn Error>>`. Every built-in
in-memory store sets `type Error = std::convert::Infallible`: a TTL that would overflow `Instant`
bounds (hundreds of years) stores the entry with no expiry (never expires) instead of erroring,
so no in-memory set path fails. `TtlSortedCacheError` (2.x's `ttl_sorted::Error`) is removed with
no replacement.

A custom `impl Cached` must declare the associated type:
```rust
impl Cached<K, V> for MyStore {
    type Error = std::convert::Infallible; // or your error type
}
```
Generic code that supports fallible custom stores should call `cache_try_set` and propagate
`Self::Error`; `cache_set` is infallible.

### `TtlSortedCache` `insert*` replaced by `set` / `set_with` and made infallible

`insert` / `insert_ttl` / `insert_evict` / `insert_ttl_evict` are replaced by plain `set(k, v)`
and the `set_with(k, v)` entry-setter builder, which covers the ttl/evict combinations via
`.ttl(Duration)` and `.evict()`. Every path now returns `Option<V>` (the displaced unexpired
value) instead of `Result`:
```rust
// Before
cache.insert_ttl(k, v, Duration::from_secs(5))?;
// After
cache.set_with(k, v).ttl(Duration::from_secs(5)).set();
```

### `iter_order` / `value_order` return `CacheValue`-wrapped values

The recency-order accessors on `LruCache`, `LruTtlCache`, and `ExpiringLruCache` share one
shape: `iter_order() -> Vec<(K, CacheValue<V, M>)>` and `value_order() -> Vec<CacheValue<V, M>>`
(`key_order` is unchanged). `CacheValue` derefs to `V` and compares against bare values; on
`LruTtlCache` the entry expiry moves from the 2.x `(Option<Instant>, V)` tuple to the
`expires_at()` accessor:
```rust
for (k, v) in cache.iter_order() {
    println!("{k}: {}", *v);
}
let exp = cache.iter_order()[0].1.expires_at(); // LruTtlCache only
```

### `contains` on single-owner stores is now peek-based (rc-only behavior change)

`CachedExt::contains` delegates to `Cached::cache_contains`, which the built-in stores implement
with a side-effect-free peek. Previously it called `cache_get`, which counted a hit/miss, promoted
LRU recency, and refreshed TTL on refresh-on-hit stores. The new implementation does none of those
things and reports expired entries as absent. No code change is required; this is a behavioral
note for callers who relied on the side effects of the old `contains`.

### `cache_set` over an existing key now promotes it to most-recently-used

Overwriting an existing key with `cache_set` moves it to most-recently-used instead of leaving it
in place. On the LRU-family stores (`LruCache`, `LruTtlCache`, `ExpiringLruCache`, and their
sharded forms) this changes which entry a capacity eviction picks in overwrite-heavy workloads:
the overwritten key survives longer, and `iter_order` / `value_order` after an overwrite change
accordingly. There is no API that writes a value without touching recency; `cache_peek` and
`cache_contains` remain non-promoting.

### `evictions` counts before `on_evict` fires

Every in-memory store increments the `evictions` counter before invoking `on_evict` for a
removed entry, on every removal path. Observable only if a callback panics (the eviction is
still counted) or reads `metrics().evictions` concurrently on a sharded store. No action
needed unless a test asserts the counter under a panicking callback.

### `retain` returns the removed count

`retain` now returns `usize` (the number of entries removed) instead of `()`, on every store
that has it: `UnboundCache`, `LruCache`, `TtlCache`, `LruTtlCache`, `TtlSortedCache`,
`ExpiringCache`, `ExpiringLruCache`, and the six sharded stores. The count includes entries the
predicate rejected plus, on the expiry-aware stores, expired entries that are removed regardless
of the predicate.

Most code needs no change: there is no `#[must_use]`, so a bare `cache.retain(|k, v| ...);`
statement still compiles and simply discards the count. Only code that bound the result as `()`
breaks, for example a wrapper function whose tail expression is the `retain` call:
```rust
// Before: fn returns (), matching retain's old return type
fn cleanup(cache: &mut LruCache<String, i32>) {
    cache.retain(|_k, v| *v > 0)
}
// After: retain now returns usize, so the tail expression needs a semicolon
fn cleanup(cache: &mut LruCache<String, i32>) {
    cache.retain(|_k, v| *v > 0);
}
```
You can now use the count directly instead of snapshotting `len()` before and after:
```rust
// Before
let before = cache.len();
cache.retain(|_k, v| *v > 0);
let removed = before - cache.len();
// After
let removed = cache.retain(|_k, v| *v > 0);
```
The sibling `TtlSortedCache::retain_latest(count, evict) -> usize` already returned a count and
is unaffected.

### `ConcurrentCachePeekAsync` is a new trait

`ConcurrentCachePeekAsync` is the async mirror of `ConcurrentCachePeek`, implemented by the six
sharded stores and available via `use cached::prelude::*;`. `RedisCache`, `RedbCache`, and
`AsyncRedisCache` implement neither peek trait: peek is an in-memory concept, and for an
IO-backed store there is no client-side recency or TTL state to skip while the read is still a
full network or disk round trip. This is additive; no action is required unless you wrote your
own concurrent-store impl.

### `TtlSortedCache` keeps the first-inserted key on overwrite

Overwriting an existing entry in `TtlSortedCache` reuses the stored key rather than the caller's
key, matching `HashMap::insert`. `on_evict` and `cache_remove_entry` therefore report the
first-inserted key, not the most recent one. This is observable only for key types whose `Eq`
ignores part of the payload; no action is needed for ordinary key types.

### `ExpiringLruCache::cache_set` reports the stored key to `on_evict`

`ExpiringLruCache::cache_set` fires `on_evict` with the stored key rather than the caller's key,
matching `LruTtlCache`. Same narrow observability as the `TtlSortedCache` case above; no action
needed for ordinary key types.

### The sharded stores collapse to one type per store; `*Base` types are gone

Each sharded store used to be two public names: a `ShardedXBase<K, V, H>` struct and a
`ShardedX<K, V>` alias over it with the hasher defaulted. 3.0 collapses this into a single
`ShardedX<K, V, H = DefaultShardHasher>` type, mirroring `HashMap<K, V, S = RandomState>`. There
is no deprecated alias: `ShardedUnboundCacheBase`, `ShardedLruCacheBase`, `ShardedTtlCacheBase`,
`ShardedLruTtlCacheBase`, `ShardedExpiringCacheBase`, and `ShardedExpiringLruCacheBase` no longer
exist anywhere in the crate.

```rust
// Before
let cache = ShardedLruCacheBase::<u32, u32, MyHasher>::builder()
    .hasher(MyHasher::default())
    .max_size(1000)
    .build()?;
// After: the turbofish names only K and V. `builder()` sits on the default-hasher impl
// block, so `ShardedLruCache::<u32, u32, MyHasher>::builder()` does not compile; the
// hasher comes from `.hasher(..)`, and `build()` yields ShardedLruCache<u32, u32, MyHasher>.
let cache = ShardedLruCache::<u32, u32>::builder()
    .hasher(MyHasher::default())
    .max_size(1000)
    .build()?;
```

If you never spelled out a `*Base` name (the overwhelming majority of call sites, since the alias
was the documented way to write these types), this needs no action: `ShardedLruCache::builder()`
and friends are unchanged, and diagnostics/rustdoc now name `ShardedLruCache` directly instead of
the internal `*Base` struct.

### Any thread-safe `std::hash::BuildHasher` now works as a sharded-store hasher

`ShardedLruCacheBuilder::hasher(h)` (and the other sharded builders) used to reject any hasher
that did not implement the crate's own `ShardHasher` trait, even a `std::hash::BuildHasher` that
the single-owner stores' `.hasher(h)` already accepted. A blanket impl closes the gap: any
`S: std::hash::BuildHasher + Clone + Send + Sync + 'static` now implements `ShardHasher`
automatically, so `std::hash::RandomState` and `ahash::RandomState` both work directly:

```rust
let cache = ShardedLruCache::<u32, u32, _>::builder()
    .hasher(std::hash::RandomState::new())
    .max_size(1000)
    .build()?;
```

If you have a custom hasher type that implements both `std::hash::BuildHasher` and a
hand-written `ShardHasher`, drop one of the two impls: a type cannot implement both (coherence
now rejects it as a duplicate `ShardHasher` impl). A custom shard-routing hasher that is not a
real hash function (numeric range, string prefix, tenant id) should not implement `BuildHasher`.

### `LruTtlCacheBuilder` / `ShardedLruTtlCacheBuilder` take the hasher in the third slot

Every builder in the crate now puts the hasher in the third generic slot and the eviction
typestate marker last:

```rust
LruTtlCacheBuilder<K, V, S = DefaultHashBuilder, E = NoEvict>
ShardedLruTtlCacheBuilder<K, V, H = DefaultShardHasher, E = NoEvict>
```

These two were the odd ones out. If you never name the builder's generics positionally (only
`<K, V>`, or you reach the hasher through `.hasher(..)`), nothing changes.

If you do name them positionally, note the failure mode: a 2.x annotation like
`LruTtlCacheBuilder<K, V, HasEvict>` still compiles at the annotation, because `HasEvict` now
binds to the hasher slot. It fails later at `.build()` with a mismatched-types or
`HasEvict: BuildHasher is not satisfied` error that does not obviously point back here. Add the
hasher as the third argument:

```rust
// 2.x
LruTtlCacheBuilder<K, V, HasEvict>
// 3.0
LruTtlCacheBuilder<K, V, DefaultHashBuilder, HasEvict>
```

`ShardedLruTtlCacheBuilder` is back to its 2.0.2 parameter order, so 2.x code naming it
positionally needs no change.

### `refresh_on_hit` / `set_refresh_on_hit` move to new `CacheRefreshOnHit` / `ConcurrentCacheRefreshOnHit` traits

These two methods are no longer part of `CacheTtl` / `ConcurrentCacheTtl`. They live on new
traits, `CacheRefreshOnHit` (single-owner `TtlCache`, `LruTtlCache`) and
`ConcurrentCacheRefreshOnHit` (concurrent `ShardedTtlCache`, `ShardedLruTtlCache`, `RedisCache`,
`AsyncRedisCache`, `RedbCache`), both re-exported at the crate root and in `cached::prelude`.

```rust
// Before
use cached::CacheTtl;
cache.set_refresh_on_hit(true);
// After
use cached::CacheRefreshOnHit;
cache.set_refresh_on_hit(true);
```

If you use `cached::prelude::*`, no action is needed. `TtlSortedCache` does not implement
`CacheRefreshOnHit` at all: in 2.x it accepted `.set_refresh_on_hit(...)` through `CacheTtl` but
silently ignored it (it always returned `false`, since its deadline-ordered index cannot support
refreshing an entry's expiry on read). Code that called `.set_refresh_on_hit()` on a
`TtlSortedCache` was getting a silent no-op and now gets a compile error.

### Redis keys use a fixed-arity, percent-escaped layout

Redis keys are built by joining `namespace:prefix:key`. Two things changed:

- Each field is percent-escaped before joining (`:` becomes `%3A`, `%` becomes `%25`), so a
  namespace, prefix, or key containing `:` or `%` no longer collides with a different
  (namespace, prefix, key) combination that produces the same joined string.
- Every field keeps its separator, including an empty namespace. A cache built with
  `.namespace("")` now writes `:my_prefix:my_key` rather than `my_prefix:my_key`. That closes a
  cross-cache deletion: the old `my_prefix:*` clear scope also covered every key of a cache whose
  namespace was `my_prefix`, so clearing the first deleted the second's entries.

```
.namespace("cached-redis-store:").prefix("my_prefix")  ->  cached-redis-store:my_prefix:my_key
.namespace("").prefix("my_prefix")                     ->  :my_prefix:my_key
.namespace("a:b").prefix("p")                          ->  a%3Ab:p:k
```

A cache with a non-empty namespace and no `:` or `%` encodes byte-identically to 2.x.

This changes the on-wire key for any cache with an empty namespace, or with `:` or `%` in its
namespace, prefix, or keys. There is no version-gated migration: an old key is simply not found
after upgrading, the entry recomputes and rewrites at the new key on next access, and the stale
old entry expires on its original TTL (or needs manual cleanup on an unbounded cache). Expect a
one-time miss per affected entry right after upgrading.
