# cached 3.0 -> 3.1 Migration (Agent Instructions)

Versions: `cached 3.0.0` -> `cached 3.1.0`

`cached_proc_macro` and `cached_proc_macro_types` did not change; leave them pinned at
`3.0.0` if pinned directly.

## Breaking changes

None. This release is purely additive.

## New APIs

Two new traits, both exported from the crate root and from `cached::prelude`. No feature
gate of their own: the trait definitions are ungated, and each implementation is gated
exactly as its store already was (`time_stores` for the TTL stores, ungated for the
`Expires`-based stores).

`CacheExpiry<K, V>`, on the single-owner stores, taking a `Borrow<Q>` key:

```rust
fn cache_peek_expires_at<Q>(&self, key: &Q) -> (Option<V>, Option<Instant>) where V: Clone;
fn peek_expires_at<Q>(&self, key: &Q) -> (Option<V>, Option<Instant>) where V: Clone;
fn cache_expires_at<Q>(&self, key: &Q) -> (bool, Option<Instant>);
fn expires_at<Q>(&self, key: &Q) -> (bool, Option<Instant>);
```

`ConcurrentCacheExpiry<K, V>`, on the sharded stores, taking `&K`:

```rust
fn cache_peek_expires_at(&self, key: &K) -> (Option<V>, Option<Instant>) where V: Clone;
fn peek_expires_at(&self, key: &K) -> (Option<V>, Option<Instant>) where V: Clone;
fn cache_expires_at(&self, key: &K) -> (bool, Option<Instant>);
fn expires_at(&self, key: &K) -> (bool, Option<Instant>);
```

Implemented by `TtlCache`, `LruTtlCache`, `TtlSortedCache`, `ExpiringCache`,
`ExpiringLruCache`, `ShardedTtlCache`, `ShardedLruTtlCache`, `ShardedExpiringCache`, and
`ShardedExpiringLruCache`. Not implemented by `RedisCache`, `AsyncRedisCache`, `RedbCache`,
or the non-expiry stores.

Return shapes, on both reads:

| value read | deadline read | meaning |
|---|---|---|
| `(None, None)` | `(false, None)` | key absent |
| `(Some(v), None)` | `(true, None)` | present, no deadline |
| `(Some(v), Some(t))`, `t` future | `(true, Some(t))` | present, live |
| `(Some(v), Some(t))`, `t` past | `(true, Some(t))` | present, expired, not removed |

`t == now` counts as expired, matching the `now >= t` liveness check the stores apply.

Use `cache_expires_at` when you only need the remaining time: it clones nothing and carries
no `V: Clone` bound. Use `cache_peek_expires_at` when you also need the value.

Both reads are side-effect free: no lru promotion, no hit/miss counters, no ttl renewal, no
removal of an expired entry.

## Detection

Nothing to detect. No existing call site changes meaning, and no signature that existed in
3.0.0 changed.

To find code that could now be simplified, search for a peek followed by a hand-rolled
expiry comparison:

```
rg 'cache_peek_with_expiry_status'
```

Such code still compiles and behaves identically. It can optionally move to
`cache_expires_at` where only the deadline is needed.

## Caveat on the `Expires`-based stores

On `ExpiringCache`, `ExpiringLruCache`, `ShardedExpiringCache`, and
`ShardedExpiringLruCache` the deadline comes from `Expires::expires_at()`, whose default
body returns `None`, while `Expires::is_expired()` remains the liveness authority. A value
type that implements only `is_expired`, which is what the crate's own docs and examples
show, reports no deadline for live and expired entries alike, so a threshold-refresh policy
built on it never fires. Override `Expires::expires_at` on the value type to use these
reads on those stores.

The presence flag is not advisory: it reports whether an entry exists regardless of what
`is_expired` says.

## Required Cargo.toml change

```toml
# Before
cached = "3.0.0"

# After
cached = "3.1.0"
```

## VERIFY

```
cargo build
cargo test
```

No new compile errors are expected from the version bump. If a call to `peek_expires_at` or
`expires_at` fails to resolve, the trait is not in scope: add `use cached::CacheExpiry;` or
`use cached::ConcurrentCacheExpiry;` (or `use cached::prelude::*;`). On the sharded stores
these are reachable only through the trait, unlike `get` / `set` / `peek`, which are also
inherent.
