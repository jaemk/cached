# cached 3.1.0 -> 3.1.1 Migration (Agent Instructions)

Versions: `cached 3.1.0` -> `cached 3.1.1`

`cached_proc_macro` and `cached_proc_macro_types` did not change; leave them pinned at
`3.0.0` if pinned directly.

## Breaking changes

None. This release is documentation and tests only. Every line added to `src/` since 3.1.0
is a doc comment, so there is no API or behavior change.

## What changed

- Documented that a custom `ty` on `#[concurrent_cached]` requires the cached function to
  return `Result<T, E>`. The macro cannot see the store's `Error` type at expansion time, so
  it always emits the fallible path. This was already enforced with a spanned compile error;
  it is now stated on the `ConcurrentCached` trait with a compiling example, and pinned by a
  `tests/ui` case.
- New example `examples/moka_custom_store.rs`, adapting a third-party cache to
  `ConcurrentCached`. `moka` is a dev-dependency for the example only and is not a dependency
  of the crate, so it does not appear in a consumer's dependency graph.
- Tests pinning the documented `Arc<T>` return pattern: a cache hit hands back the same
  allocation rather than a copy, on `#[cached]` and on `#[once]`.

## Detection

Nothing to detect. No existing call site changes meaning.
