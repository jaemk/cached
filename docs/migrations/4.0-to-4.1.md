# cached 4.0 -> 4.1 Migration (Agent Instructions)

Versions: `cached 4.0.4` -> `cached 4.1.0`

`cached_proc_macro` and `cached_proc_macro_types` did not change; leave them pinned at
`3.0.1` and `3.0.0` respectively if pinned directly.

## Breaking changes

None. This release is purely additive.

## New APIs

Feature `redb_store`. A new struct, exported from the crate root and `cached::stores`:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Default)]
#[non_exhaustive]
pub struct RedbCacheStats {
    pub entries: usize,     // every stored entry, expired and undecodable included
    pub expired: usize,     // decodable entries with age >= the current TTL; 0 with no TTL
    pub undecodable: usize,
    pub oldest: Option<SystemTime>, // min `created_at` over decodable entries
    pub newest: Option<SystemTime>, // max `created_at` over decodable entries
}
```

Two inherent methods on `RedbCache<K, V>`:

```rust
pub fn scan_stats(&self) -> Result<RedbCacheStats, RedbCacheError>;
pub async fn async_scan_stats(&self) -> Result<RedbCacheStats, RedbCacheError>; // feature `async`
```

The scan is O(n), runs under one read transaction, deserializes every stored `V`, and never
writes: undecodable entries are counted (in both deserialization modes), not self-healed or
returned as errors, and expired entries are counted, not removed. `cache_size()` still returns
`Ok(None)` and `metrics().entry_count` is still `None`.

`RedbCacheStats` is `#[non_exhaustive]`: build one from `Default` and assign fields; do not
use a struct literal or an exhaustive destructure.

## Detection

Nothing to detect. No existing call site changes meaning, and no signature that existed in
4.0.4 changed.

To find code that could now be simplified, search for direct reads of the redb cache file:

```
rg 'ReadOnlyDatabase|cached_disk_cache|CachedDiskValue'
```

Such code still works while the on-disk format is unchanged. It can optionally move to
`cache.scan_stats()`, which uses the live handle (no second open of the locked file).

